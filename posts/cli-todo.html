cli-todo：300 行代码的终端待办工具

2026-09-18/7 min read/#Node.js#CLI#小工具

受够了图形待办软件的启动速度，用 Node.js 写了一个住在终端里的待办工具。

动机#

我的待办列表和终端待在一起：写代码的间隙冒出一个念头，切去图形软件点三层菜单回来，思路已经断了。于是决定让待办就住在终端里——一个命令添加，一个命令完成，一个命令看今天。

命令设计#

bash
$ todo add "把容器查询那篇写完" --tag css
$ todo ls --today
$ todo done 3
$ todo rm 3

原则只有一条：常用命令必须能盲打。所以 add / ls / done 三个词最短，参数全部可选。

数据结构#

没有引数据库，一个 JSON 文件就是全部存储，位于 ~/.todo.json：

json
{
  "nextId": 12,
  "items": [
    { "id": 3, "text": "把容器查询那篇写完", "tag": "css", "done": true, "createdAt": "2026-09-20T10:12:00+08:00" }
  ]
}

每条命令都是「读文件 → 改内存 → 写回」，写入用临时文件 + rename 保证原子性，杜绝写一半断电留下的半个 JSON。

彩色输出#

ANSI 转义序列手写即可，不必引依赖：

javascript
const paint = (code, s) => "\u001b[" + code + "m" + s + "\u001b[0m";
const green = (s) => paint(32, s);
const dim = (s) => paint(2, s);

// 输出一行待办：未完成绿色，已完成置灰加删除线
console.log(item.done ? dim("~~ " + item.text + " ~~") : green("• " + item.text));

同时检测 process.stdout.isTTY，管道输出时自动退化成纯文本，方便 todo ls | grep。

发布#

npm publish 之后全局安装即用。300 行，零运行时依赖，这是它最让我满意的地方——五年后 npm i -g cli-todo，照样跑。
